# Owner UX Stabilization — долговечный продуктовый контракт

## Статус и назначение

Этот документ фиксирует принятый смысл stabilization перед Tasks `114-124`. Будущие задачи могут
полностью менять визуальную реализацию, но не должны возвращать устранённые product/UX-регрессии.

## Системные правила

- Доступный недельный календарь позволяет выбрать день; `today` и выбранный день — разные состояния,
  а выбор меняет фактические или запланированные данные экрана.
- Один пользовательский intent не получает несколько равноправных primary entry points и не
  дублирует глобальную навигацию без нового контекста.
- Blocking modal/sheet использует общий document scroll lock, сохраняет внутренний scroll и
  восстанавливает исходную позицию страницы. Mobile Web/TMA учитывают visual viewport: focused input,
  результаты и основные действия остаются достижимыми над клавиатурой.
- Недоступные capability-dependent действия не показываются. В частности, trainer feedback требует
  актуальную активную связь с тренером.
- Compact-first не резервирует пустую высоту. Полностью сохранённое упражнение может автоматически
  свернуться до понятного summary и остаётся раскрываемым; pending/error/unsaved state не сворачивается.
- Для Save actions persisted state означает disabled. Только валидное изменение включает Save;
  success снова выключает его, а failed request сохраняет dirty values и возможность retry.

## Доменные правила

### Today и cardio

- Прошлый день показывает фактическое, будущий — запланированное.
- Незапланированная пустая cardio-форма не является постоянным primary content в `Сегодня`.
- В незапланированный день без cardio sessions секция не создаёт entry prompt. При наличии плана
  сначала показывается planned state; при наличии completed session сначала показывается результат.
- Planned/completed cardio показывается как состояние выбранного дня; completed выглядит как результат.
- Дополнительная запись открывается отдельным secondary действием после состояния дня. Создание из
  `Сегодня` фиксирует факт; планирование принадлежит `Плану`.

### Nutrition search

- В picker сначала идёт явный вход в поиск по штрихкоду, затем поиск по названию или бренду;
  secondary способы добавления не разрывают эту последовательность.
- Поиск использует реальный local-first data flow и автоматически продолжает предусмотренным внешним
  provider при пустом локальном результате.
- Внешний результат не является read-only тупиком: явное действие выбора сохраняет нормализованную
  карточку в `Мои продукты` и сразу переводит пользователя к выбору порции. Повторный выбор того же
  barcode использует уже сохранённую локальную карточку.
- User foods остаются частью локального каталога. Provider disabled/unavailable и ошибки показываются
  честно; статические фиктивные результаты запрещены.
- Production release сохраняет включённый и идентифицированный внешний provider. Provider query не
  меняется на синтаксис, который превращает обычный пользовательский запрос в пустой exact phrase.
- Доменный статус `fasted` называется в UI `День без приёмов пищи` и объясняет последствие отметки.

### Progress report PDF

- В Web действие запускает системную печать, из которой фактически сохраняется PDF.
- В TMA действие реально открывает тот же защищённый report URL во внешнем браузере через
  `Telegram.WebApp.openLink`; URL сохраняет period, custom dates и `client_id`.
- Прямой browser GET этого report URL обслуживается приватным SPA shell, а не JSON `404`; штатный
  production smoke проверяет `/app/report?period=days_30`.
- Если platform handoff недоступен, пользователь получает обычную actionable browser link. Простая
  инструкция без действия не считается экспортом или сохранением PDF.

### Exercise catalog

- Client catalog rows compact-first: title, полезная metadata и основной intent находятся в одной
  доступной строке без отдельного ряда, резервирующего пустую высоту.
- Строка остаётся keyboard/touch action с минимум 44 px target; подробности не удаляются и открываются
  по явному accessible name.

### Program, Profile и Trainer

- Один экран выбора программы имеет один entry point. При активной программе initial-selection promo
  отсутствует, а повторный подбор запускается отдельным осознанным действием.
- Program stepper сохраняет корректные circles/numbers/labels на `360x800`, `390x844`, `430x932`.
- Крупные Profile sections используют единый semantic disclosure с понятными icons и keyboard/focus
  semantics. Completion prompt не показывается при `3/3`.
- `Обратная связь тренера` отсутствует без актуальной активной trainer relationship на всех client
  surfaces.

## Regression gate

Task `124A` повторно проверяет все findings `01-19` из Owner UX Stabilization. Новая визуальная
реализация допустима; возврат перечисленного поведения — нет.

## Owner gate

Stabilization release выполняется до Task `114`. После production smoke работа останавливается на
owner verification. Task `114` нельзя начинать без точной явной команды владельца:
`Stabilization принята. Можно переходить к Task 114.`
