# Политика применения новых skills к выполненным задачам

## Решение

Tasks `00-48` не выполняются повторно; task `49` является текущим resume-исключением и после завершения также не переигрывается. Их task-файлы получили актуальную строку `Рекомендуемые skills`, чтобы было видно, какие профильные роли отвечают за соответствующую подсистему сегодня.

## Mobile/TMA-first without rerunning completed tasks

Task `50A` проверяет только shared platform foundation и создаёт continuous gate. Она не повторяет feature work `00-49`. Feature-specific проблемы completed scope остаются входом task `76`, если они не являются общим P0/P1 blocker для всех следующих мобильных задач.

## Почему одного финального audit недостаточно

Финальный gate проверяет интегрированный релиз, но он слишком поздний и широкий для глубокого предметного review каждой формулы, accessibility pattern или privacy boundary. Поэтому перед usability testing добавлена task `76` - отдельный ретроспективный audit фактического кода актуальными skills.

## Что разрешено task 76

- проверить текущий результат, tests, migrations и docs;
- закрыть подтверждённые P0/P1;
- выполнить небольшой безопасный P2;
- вынести крупный P2 владельцу;
- зафиксировать области, где исправления не нужны.

## Что запрещено

- переигрывать исторические tasks;
- переписывать архитектуру без finding;
- запускать третий redesign;
- добавлять post-release функции;
- заявлять проблему только потому, что старый task не называл новый skill.

task `79` использует результаты task `76`, реальных сессий task `77` и operational evidence task `78` как последние входы для go/no-go.
