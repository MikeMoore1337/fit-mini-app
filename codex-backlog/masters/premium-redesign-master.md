# Your Fitness Coach - Premium Redesign

## Цель пакета

Поэтапно переработать UX/UI Your Fitness Coach так, чтобы:

- лендинг выглядел современно и убедительно;
- веб-приложение воспринималось как полноценный коммерческий продукт, а не набор форм и карточек;
- Telegram Mini App был действительно mobile-first;
- ключевые действия пользователя выполнялись быстрее и понятнее;
- интерфейс имел единый узнаваемый визуальный язык;
- дизайн выглядел современно, дорого и профессионально;
- анимации улучшали восприятие и обратную связь, а не мешали работе;
- текущая бизнес-логика, данные и права доступа были сохранены.

Целевое направление:

```text
premium sport-tech
graphite / warm neutral / lime
strong typography
clear hierarchy
fewer borders
fewer nested cards
purposeful motion
mobile-first interactions
```

## Почему задача разбита

Не отдавай Codex весь редизайн одним запросом.

Каждый файл ниже - самостоятельный этап, который можно выполнять в отдельной Codex-сессии.
Это уменьшает расход контекста и снижает риск, что Codex одновременно затронет слишком много экранов.

После каждого этапа изменения должны быть проверены и закоммичены.
Следующий этап начинает работу с уже изменённым репозиторием.

## Взаимодействие с Food + Training Platform и AI Coach

Если эти крупные функции ещё не объединены с основной веткой, рекомендуется:

1. выполнить `01_BASELINE_AUDIT_AND_TARGET_DESIGN.md`;
2. при желании выполнить `02_DESIGN_SYSTEM_FOUNDATION.md`;
3. затем объединить стабильные функциональные этапы Food + Training Platform и AI Coach;
4. продолжить с `03_APP_SHELL_AND_NAVIGATION.md`.

Причина: навигация, "Сегодня", питание и конечный UI должны проектироваться по актуальному набору функций.

Если Food/AI уже реализованы - учитывать их как часть текущего продукта.

# Этап 01. Baseline UX/UI audit и целевая модель редизайна

Рекомендуемые skills: `$ui-audit`, затем `$product-designer`.

## Контекст проекта

Репозиторий: `https://github.com/MikeMoore1337/fit-mini-app`
Продакшен: `https://your-fitness-coach.ru/`

Your Fitness Coach - один продукт с общим frontend/backend, доступный как веб-приложение и Telegram Mini App.

Перед изменениями обязательно:
1. прочитать `AGENTS.md`;
2. проверить актуальный `docs/`;
3. изучить текущее состояние затрагиваемых компонентов и тестов;
4. проверить последние коммиты, потому что параллельно могут быть реализованы Food + Training Platform и AI Coach;
5. не дублировать уже появившуюся функциональность;
6. не откатывать и не переписывать чужие изменения только ради удобства редизайна.

Если структура проекта изменилась с момента подготовки задачи, адаптировать пути к фактическому репозиторию, сохранив требования задачи.

## Общие продуктовые ограничения

- Не переписывать приложение с нуля.
- Не менять бизнес-логику без прямой необходимости.
- Не создавать отдельный frontend для Web и Telegram Mini App.
- Сохранять общий продуктовый язык, компоненты и UX-паттерны.
- Web и Telegram Mini App используют одну фирменную пару YFC Light/YFC Dark и одинаковые semantic product colors; platform-specific различия не создают отдельный visual design.
- Не копировать буквально дизайн Apple Fitness, Whoop, Linear, FatSecret, Fitness Online или других продуктов.
- Не подключать тяжёлый UI-framework или animation-framework без доказанной необходимости.
- Предпочитать существующий React/TypeScript/CSS стек, CSS transitions/animations и Web APIs.
- Не добавлять эффекты ради эффектов.
- Не превращать интерфейс в glassmorphism/neon/crypto-style.
- Визуальная цель: `premium sport-tech`.
- Сохранить фирменный лаймовый акцент, но использовать его дозированно.
- Основная система: графитовые/нейтральные поверхности + светлые нейтральные поверхности + фирменный лайм.
- Интерфейс должен быть удобен прежде всего на телефоне, но Web desktop не должен выглядеть растянутой мобильной версией.

## Инженерный процесс

Следовать `AGENTS.md`.

Для каждого законченного этапа:
1. реализовать только scope этого файла;
2. запустить связанные тесты/проверки;
3. визуально проверить реальные изменённые экраны через Playwright;
4. проверить `git diff`;
5. исправить регрессии;
6. сделать отдельный логический Git-коммит;
7. в отчёте перечислить реально запущенные проверки и hash коммита.

Не заявлять, что проверка выполнена, если она фактически не запускалась.
Скриншоты, trace, временные отчёты и прочие артефакты хранить только в `.artifacts/` и не коммитить.


## Зачем нужен этот этап

Перед изменением компонентов нужен фактический baseline. Нельзя строить редизайн только по исходникам CSS.
Нужно увидеть реальные Web и mobile состояния, понять текущие проблемы и зафиксировать минимальную целевую модель,
которая станет ориентиром для остальных этапов.

## Scope

Провести read-only аудит:

- лендинга;
- основного пользовательского приложения;
- активной тренировки;
- прогресса;
- программ;
- упражнений;
- питания;
- профиля;
- кабинета тренера;
- Telegram-specific слоя, насколько его можно достоверно проверить локально.

Проверить минимум viewport:

- 1440;
- 1280;
- 768;
- 390;
- 360 px.

Проверить существующие состояния, где применимо:

- normal/populated;
- empty;
- loading;
- error;
- selected/active;
- hover;
- focus;
- disabled;
- modal/drawer;
- длинный текст;
- маленький экран.

Зафиксировать проблемы по P0-P3.

Отдельно оценить:

- информационную иерархию;
- количество одновременно конкурирующих CTA;
- чрезмерное использование карточек/рамок;
- плотность и вертикальный ритм;
- размеры touch targets;
- навигацию;
- desktop vs mobile composition;
- типографику;
- цветовую систему;
- визуальную согласованность Web/Telegram;
- accessibility;
- animation/motion baseline;
- layout shifts/overflow;
- формы;
- таблицы/списки;
- состояние во время тренировки.

## Что не входит

- Не менять продуктовый код.
- Не исправлять найденные дефекты по пути.
- Не коммитить большой audit report в `docs/`.
- Не придумывать новые продуктовые функции.

## Требования

1. Использовать реальный render через Playwright или существующую browser-инфраструктуру.
2. Хранить screenshots/report в `.artifacts/ui-redesign/baseline/`.
3. В итоговом отчёте определить 5-10 главных UX/UI проблем.
4. Указать, какие проблемы решаются системой, а не точечными CSS-правками.
5. Определить эталонные экраны для последующего редизайна.
6. Сформулировать арт-дирекцию:
   - premium sport-tech;
   - restrained;
   - data-driven;
   - performance-oriented;
   - lime как акцент;
   - нейтральные поверхности;
   - сильная типографическая иерархия;
   - минимум декоративного шума.
7. Зафиксировать правила cards/borders/shadows/accent/motion.
8. Если Food или AI Coach уже появились, включить их в карту информационной архитектуры.
9. Считать необоснованное расхождение product colors/components между Mobile Web и TMA дефектом; platform chrome/safe-area/runtime различия допустимы.

## Проверка

- Просмотреть все screenshots.
- Убедиться, что audit основан на фактическом render.
- Проверить отсутствие изменений tracked files через `git diff`.

## Acceptance criteria

- Есть visual baseline в `.artifacts/`.
- Есть P0-P3 findings.
- Есть целевая модель визуального языка.
- Есть карта основных навигационных разделов.
- Определено, какие Web/TMA различия действительно platform-specific; отдельная product palette для TMA не допускается.
- Production-код не изменён.

## Коммит

Если tracked files не менялись - commit не создавать.

## Scope

Проверить актуальные:

- `frontend/src/styles/legacy.css`;
- `frontend/src/styles/react.css`;
- `frontend/src/shared/ui/*`;
- `frontend/src/shared/theme.ts`;
- Telegram platform/theme adapter;
- landing-specific tokens.

Создать/упорядочить, где уместно:

- typography scale;
- spacing scale;
- radius scale;
- border/surface/elevation tokens;
- semantic colors;
- content widths;
- focus ring;
- touch target sizes;
- motion duration/easing tokens;
- disabled/loading states;
- button variants;
- icon button;
- field/input/select;
- card/surface;
- section header;
- badge/status;
- metric/value;
- tabs/segmented controls;
- skeleton/loading;
- empty/error state.

## Не входит

- Полный редизайн конкретных экранов.
- Route refactor.
- Backend changes.
- Подключение Tailwind/MUI/Ant/Chakra.
- Массовая миграция всех legacy классов одним коммитом.

## Палитра

Сохранить брендовый lime как основной browser accent.

Направление:

```text
dark:
  background = near-black graphite
  surface = neutral dark graphite/green
  text = warm off-white
  muted = neutral gray-green
  accent = brand lime

light:
  background = warm off-white
  surface = white/warm neutral
  text = deep graphite/green-black
  muted = neutral gray-green
  accent = brand lime
```

Telegram использует `colorScheme` для выбора общей YFC Light/Dark темы. `themeParams` не должны определять отдельную product palette.

## Typography

- Разделить display/page title/section title/body/label/caption/metric.
- Не делать всё bold.
- Снизить ощущение одинаковых административных карточек.
- Цифровые метрики должны быстро считываться.

## Geometry

- Один согласованный набор radii.
- Основные mobile controls около 44px или больше по hit area.
- Не использовать тень на каждой карточке.
- Border отделяет реальные уровни поверхности, а не обводит всё.

## Motion

Создать semantic tokens для:

- fast feedback;
- standard transition;
- panel/section entrance;
- progress/state change.

Обязательно учитывать `prefers-reduced-motion`.

## Telegram

Не создавать динамическую product palette из Telegram theme params. Semantic product tokens одинаковы для Web/TMA; Telegram adapter использует `colorScheme` для выбора YFC Light/Dark и отдельно интегрирует shell/safe-area behavior.

## Проверка

Запустить:

- typecheck;
- lint;
- format check;
- unit tests затронутых UI primitives;
- build.

Визуально проверить несколько существующих экранов light/dark.

## Acceptance criteria

- Есть единая система основных tokens.
- Базовые buttons/fields/surfaces/states согласованы.
- Telegram theme mapping работает.
- `prefers-reduced-motion` предусмотрен.
- Не добавлен тяжёлый UI framework.
- Нет массового unscoped refactor.

## Коммит

`refactor(ui): establish premium design system foundation`

- Не копировать буквально дизайн Apple Fitness, Whoop, Linear, FatSecret, Fitness Online или других продуктов.
- Не подключать тяжёлый UI-framework или animation-framework без доказанной необходимости.
- Предпочитать существующий React/TypeScript/CSS стек, CSS transitions/animations и Web APIs.
- Не добавлять эффекты ради эффектов.
- Не превращать интерфейс в glassmorphism/neon/crypto-style.
- Визуальная цель: `premium sport-tech`.
- Сохранить фирменный лаймовый акцент, но использовать его дозированно.
- Основная система: графитовые/нейтральные поверхности + светлые нейтральные поверхности + фирменный лайм.
- Интерфейс должен быть удобен прежде всего на телефоне, но Web desktop не должен выглядеть растянутой мобильной версией.

## Инженерный процесс

Следовать `AGENTS.md`.

1. реализовать только scope этого файла;
2. запустить связанные тесты/проверки;
3. визуально проверить реальные изменённые экраны через Playwright;
4. проверить `git diff`;
5. исправить регрессии;
6. сделать отдельный логический Git-коммит;
7. в отчёте перечислить реально запущенные проверки и hash коммита.

Не заявлять, что проверка выполнена, если она фактически не запускалась.
Скриншоты, trace, временные отчёты и прочие артефакты хранить только в `.artifacts/` и не коммитить.
