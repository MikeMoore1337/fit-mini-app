# Детерминированная адаптация тренировки на сегодня

Адаптация меняет только одну материализованную тренировку на сегодня. Она не создаёт новую
программу, не изменяет будущие тренировки и не использует AI. Текущая версия правил —
`workout-adaptation-v1`.

## Поддерживаемые причины

- мало времени;
- недоступно оборудование для выбранного упражнения;
- явная замена упражнения;
- другое место тренировки с другим набором оборудования.

Отдельный вариант `pain_or_injury` ничего не меняет. Backend возвращает `safety_stop` и понятное
сообщение: приложение не подбирает медицинскую замену, при боли нужно прекратить проблемное
упражнение и обратиться к квалифицированному специалисту. Этот вариант доступен и после начала
тренировки, но применяемого preview у него нет.

## Правила ограничения по времени

Расчётная длительность нужна только для сравнения вариантов и не считается точным прогнозом.
Для каждого упражнения учитываются:

- `45` секунд на каждый назначенный подход;
- назначенный отдых между подходами;
- `60` секунд на переход и подготовку упражнения.

Порядок, заданный автором программы, служит явным источником приоритета. Первые два одиночных
упражнения или суперсет-блока считаются основой и не удаляются. Упражнения, основная мышечная
группа которых совпадает с приоритетом активного тренировочного блока, также сохраняются.
Остальные блоки удаляются с конца, пока расчётное время не укладывается в бюджет. Две части
суперсета всегда сохраняются или удаляются вместе.

Если бюджет меньше расчётного времени сохранённой основы, preview сообщает об этом и не удаляет
основные или приоритетные упражнения ради формального совпадения с числом минут.

## Замены и оборудование

Источник эквивалентности — только подготовленные пары `exercise_alternatives`. Совпадение основной
мышечной группы само по себе не считается основанием для замены. Кандидат допустим, только если
всё его каноническое `exercise_equipment` входит в явно указанный пользователем набор доступного
оборудования. Упражнение без структурированных данных об оборудовании не считается совместимым по
умолчанию.

Для причины `replace_exercise` пользователь сам выбирает одну совместимую проверенную альтернативу.
Для недоступного оборудования backend выбирает первый совместимый вариант в стабильной сортировке
по названию и ID. Для другого места то же правило применяется ко всем несовместимым упражнениям.
Случайных замен нет. Если хотя бы для одного упражнения нет проверенного варианта, изменение не
применяется частично.

## Preview, применение и история

API:

- `GET /api/v1/workouts/{workout_id}/exercises/{workout_exercise_id}/alternatives` возвращает
  только проверенные варианты, совместимые с переданным оборудованием;
- `POST /api/v1/workouts/{workout_id}/adaptations/preview` строит diff без записи в БД;
- `POST /api/v1/workouts/{workout_id}/adaptations/apply` повторно рассчитывает правила и применяет
  diff только после явного подтверждения с `preview_token`.

Обычное изменение состава разрешено только до начала запланированной тренировки на текущую дату.
Apply блокирует назначенную программу, повторно проверяет snapshot и выполняет изменение в одной
транзакции. Если тренировка или условия отличаются от preview, возвращается `409` и требуется новый
preview. Повтор того же apply с тем же `preview_token` идемпотентен: backend возвращает уже
созданную audit-запись и не применяет diff второй раз.

`workout_adaptations` хранит причину, исходный snapshot, фактически применённый diff, входные
условия, версию правил и локальное время владельца аккаунта. История завершённой тренировки
возвращает фактический состав после изменений и audit-записи. Очистка самой истории тренировок
удаляет связанные записи адаптации вместе с тренировкой.

Права доступа определяются владельцем `user_programs`: ID пользователя из frontend не принимается.
Preview и apply не могут читать или менять тренировку другого аккаунта.
