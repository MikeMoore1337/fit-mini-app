# Постепенное знакомство пользователя с продуктом

После успешной авторизации новый и возвращающийся пользователь Web, Mobile Web и Telegram Mini App
сразу открывает `/app` внутри обычного app shell. Состояние профиля не перенаправляет на
`/onboarding` и не блокирует разделы `Сегодня`, `Программа`, `Питание` и `Прогресс` в пределах их
собственных требований к данным.

Пользователь без активной программы видит на `Сегодня` одно главное действие
`Создать свою программу` и вторичное `Выбрать готовую`. Предложение `Заполнить профиль` остаётся
необязательным и объясняет пользу данных. Отдельный `/onboarding` сохранён как совместимый
необязательный маршрут для старых ссылок, но не входит в critical path первого запуска.

## Контракт состояния

`GET /api/v1/me` и ответ `PATCH /api/v1/me/profile` содержат объект `onboarding`:

```json
{
  "status": "required",
  "required_fields": ["goal"],
  "missing_fields": ["goal"]
}
```

Состояние вычисляется из основной модели `UserProfile`; отдельной модели для onboarding или
профиля нет. Поле `status: required` и список `required_fields` сохранены как совместимый API
summary для старых клиентов. Они не означают обязательный frontend gate. Канонические значения
цели: `fat_loss`, `muscle_gain`, `maintenance`, `recomposition`.

Цель, возраст, рост, вес, пол, активность и параметры тренировок не являются блокером первого
запуска. Они запрашиваются контекстно только там, где функция действительно использует данные.
Уже сохранённые значения продолжают использоваться для рекомендаций и начального заполнения форм;
legacy `required` и `complete` records не изменяются и не удаляются.

## Контракт событий активации

Frontend публикует события через единый privacy-safe контракт `yfc:product-event`. Подробная
карта продуктовой аналитики хранится в owner-only документации и не входит в публичный Git.
Текущая реализация ничего не отправляет во внешний сервис.

Совместимый необязательный маршрут `/onboarding` по-прежнему поддерживает события:

- `onboarding_started`;
- `onboarding_completed`;
- `onboarding_next_action_selected` с `next_action`: `today`, `nutrition`, `programs` или
  `continuation`.

Эти события нельзя интерпретировать как обязательную активацию нового пользователя: обычный
first-run больше не обязан их публиковать. Каждое событие содержит только `surface` (`web` или
`telegram`) и безопасный системный envelope.
В события нельзя добавлять цель, возраст, рост, вес, пол, user ID или другие значения профиля и
питания.
