# Детерминированные рекомендации прогрессии нагрузки

`GET /api/v1/workouts/today` возвращает для каждого упражнения необязательное поле
`progression_guidance`. Оно рассчитывается backend при чтении и не сохраняет отдельную оценку,
не изменяет программу, будущую тренировку, назначенные подходы или фактический вес.

## Источник фактов

Ruleset `progression-guidance-v1` использует только:

- число и диапазон повторений текущего назначения;
- завершённые рабочие подходы (`working` и legacy `null`);
- фактические повторы и внешнюю нагрузку;
- необязательный RIR и явную отметку отказа;
- последовательность завершённых тренировок того же упражнения в том же назначении программы;
- совпадающие prescription и training-block context.

Разминка и дроп-сеты не входят в decision rule. Незаполненный подход, отсутствие повторов или
нагрузки, смешанная нагрузка внутри сессии и неподдерживаемая свободная запись назначения не
подменяются нулями или догадкой. Простой prescription распознаётся только как одно положительное
число или диапазон через `-`, `–` или `—`.

Completion feedback (`легче ожидаемого`, `нормально`, `тяжелее ожидаемого`) возвращается среди
фактов сессии, если он есть, но в ruleset v1 не меняет outcome. Заметка пользователя не передаётся
в guidance. Это сохраняет feedback вторичным наблюдением и не создаёт recovery score.

## Outcomes

- `consider_progressing`: верхняя граница достигнута во всех рабочих подходах двух последних
  сопоставимых сессий при полном записанном положительном запасе повторов без отказа. Если RIR
  отсутствует или покрыт не полностью, требуются три стабильные сессии.
- `hold`: сопоставимых фактов уже достаточно для осторожного ответа, но правило устойчивого
  увеличения или снижения не выполнено. Отметка `RIR = 0` или отказ не усиливает рекомендацию.
- `consider_reducing`: во всех рабочих подходах двух последних сопоставимых сессий на одной
  нагрузке повторы оставались ниже нижней границы. Это product heuristic, а не диагноз усталости,
  восстановления или перетренированности.
- `review`: нет двух полных сопоставимых сессий, изменился контекст программы/блока или prescription
  нельзя безопасно разобрать.

`reason_keys`, счётчики и максимум три последние сессии образуют explainable evidence для UI и
будущего read-only AI consumer. AI не должен пересчитывать progression самостоятельно.

## Шаг нагрузки и единицы

Engine сохраняет явную единицу `kg` или `lb`. Production-журнал сейчас записывает внешнюю нагрузку
в `kg`, поэтому ответ API использует `kg`.

Точный `suggested_weight` появляется только при переданном достоверном configured increment.
Текущая модель оборудования не хранит индивидуальный доступный шаг блинов, гантелей или тренажёра,
поэтому production builder передаёт `null` и UI показывает качественное действие без выдуманного
`+2,5 кг`. Контракт engine и UI поддерживает точный шаг для будущего канонического источника.

## UX и recovery

Подсказка находится внутри exercise region перед записью подходов. Главное действие active workout
остаётся `Завершить подход`; guidance не получает lime-primary CTA. `Почему?` использует shared
`DisclosureIcon` и показывает плоскую историю с датами, весом, повторениями и покрытием RIR.

Пользователь может скрыть подсказку в текущем render. Если API когда-либо вернёт точный вес из
configured increment, кнопка явно подставляет его только в незавершённые рабочие подходы через
существующую duplicate-safe offline queue. Повторное касание, reconnect и reload не применяют
изменение второй раз. Evidence guidance не сохраняется в `localStorage`: offline snapshot намеренно
удаляет поле `progression_guidance`. Старые и новые snapshots без него остаются валидными, а feature
region просто не показывается до получения свежих server facts.

События `progression_suggestion_shown` и `progression_suggestion_dismissed` не содержат exercise,
вес, повторы, RIR, outcome или идентификаторы пользователя.
