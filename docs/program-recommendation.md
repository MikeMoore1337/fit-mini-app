# Детерминированный подбор программы

Подбор программы использует только существующие системные public-шаблоны. Он не генерирует
упражнения, не вызывает AI/LLM и не создаёт либо активирует `UserProgram`. Рекомендация ведёт в
существующий процесс:

`подобрать -> посмотреть состав -> при желании изменить личную копию -> явно запустить`.

Скрытый пользователем системный шаблон не участвует в подборе. Личные, клиентские и созданные
администратором шаблоны также не входят в каталог рекомендаций: решение опирается на
контролируемые системные метаданные и остаётся одинаковым для одинаковых входов.

## Входные данные

`POST /api/v1/programs/templates/recommendation` принимает необязательные переопределения:

- `goal`: `fat_loss`, `recomposition`, `maintenance`, `muscle_gain` или `strength`;
- `experience`: `beginner`, `intermediate` или `advanced`;
- `workouts_per_week`: от 1 до 8 тренировок за цикл;
- `training_location`: `gym`, `home` или `other`;
- `available_equipment_ids`: контролируемые идентификаторы оборудования из exercise domain.

Если цель, опыт или частота не переданы, backend использует соответственно `profile.goal`,
`profile.level` и `profile.workouts_per_week`. Отсутствующие обязательные значения возвращают
`needs_input`, а не неявное предположение. Место тренировки — поясняющий факт; совместимость с
инвентарём фильтруется строго только при явной передаче `available_equipment_ids`. Пустой список
означает, что отдельного инвентаря нет. `bodyweight` не считается отдельным предметом инвентаря.
В текущем домене нет других проверенных structured constraints для программ. Подбор не собирает
жалобы, не диагностирует травмы и не делает медицинских выводов.

## Пользовательский мастер

Раздел `План` открывает подбор из пустого состояния текущей программы и из отдельного блока перед
библиотекой шаблонов. Мастер последовательно спрашивает цель, опыт силовых тренировок, устойчивую
частоту, место и доступное оборудование. Канонические значения API скрыты за понятными русскими
названиями. Достоверные `goal`, `level` и `workouts_per_week` подставляются из профиля, но изменение
ответа внутри мастера не обновляет профиль.

Назад можно вернуться без потери ответов. Результат показывает причину выбора, цель, уровень,
частоту, понятное описание схемы тренировок, проверенные факты и ограничения. Пользователь сначала
открывает состав, а затем отдельно выбирает расписание и запускает шаблон. Личная копия создаётся
через существующий конструктор и не запускается молча. При отсутствии совпадения остаются три пути:
изменить ответы, открыть библиотеку вручную или создать свою программу.

Мастер не показывает проценты совпадения, не использует AI и явно сообщает, что не оценивает боль,
травмы или медицинские ограничения. Замена активной программы продолжает требовать отдельного
подтверждения в существующем процессе запуска.

## Метаданные шаблона

`ProgramTemplate.split_type` — nullable структурированное поле:

- `full_body` — всё тело за тренировку;
- `upper_lower` — верх/низ;
- `push_pull_legs` — тяни/толкай/ноги;
- `body_part` — дни по группам мышц;
- `hybrid` — комбинированный сплит.

Миграция `0041_program_split` заполняет поле только для известных системных шаблонов. Legacy или
custom-шаблон с неизвестным split остаётся `NULL` и не рекомендуется: backend не угадывает формат
из title/slug. Требования к оборудованию вычисляются по фактическим упражнениям и их
`exercise_equipment`, введённым в task 23; отдельной копии этих данных у программы нет.

## Таблица решений

Сначала исключаются несовместимые кандидаты: неизвестный split, более высокий уровень шаблона,
разница частоты больше одной тренировки, несовместимое оборудование и неподходящая цель.
Восьмидневный последовательный цикл совместим только с входом `8`, поскольку это не восемь
тренировок в календарную неделю.

Допустимые цели шаблонов перечислены в порядке приоритета:

| Цель пользователя | Цели шаблона |
| --- | --- |
| Снижение веса | `fat_loss` -> `recomposition` -> `maintenance` |
| Улучшение композиции тела | `recomposition` -> `muscle_gain` -> `maintenance` |
| Поддержание формы | `maintenance` -> `recomposition` -> `muscle_gain` |
| Набор мышечной массы | `muscle_gain` -> `recomposition` |
| Развитие силы | только `strength` |

Текущий каталог не содержит проверенного `strength`-шаблона, поэтому такая цель даёт
контролируемый `no_match`; обычная программа набора мышц не переименовывается в силовую.

Предпочтения split после проверки цели и точности частоты:

| Опыт | 2-3 тренировки | 4 тренировки | 5+ тренировок |
| --- | --- | --- | --- |
| Начальный | Full Body -> Upper/Lower -> Hybrid | Full Body -> Upper/Lower -> Hybrid | Full Body -> Upper/Lower -> Hybrid |
| Средний | Full Body -> Upper/Lower -> Hybrid -> Body Part | Upper/Lower -> Hybrid -> Full Body -> Body Part | Body Part -> PPL -> Upper/Lower -> Hybrid -> Full Body |
| Продвинутый | Full Body -> Upper/Lower -> Hybrid | Upper/Lower -> Hybrid -> Body Part -> Full Body | PPL -> Body Part -> Hybrid -> Upper/Lower -> Full Body |

Уровень шаблона может быть равен уровню пользователя или быть ниже, но не выше. Итоговая
сортировка использует кортеж:

1. приоритет совместимой цели;
2. абсолютную разницу числа тренировок;
3. приоритет split из таблицы;
4. разницу уровня;
5. `slug`, затем `id` как стабильный tie-break.

## Ответ и ограничения

Ответ имеет статус `recommended`, `needs_input` или `no_match`. Для рекомендации возвращаются
полный доступный для preview шаблон, текстовая причина, проверяемые `fit_facts`, честные
`limitations` и до двух альтернатив. Проценты совпадения и confidence score не рассчитываются.

`requires_explicit_start=true` фиксирует workflow-контракт. Запуск по-прежнему выполняется только
существующим `POST /templates/{template_id}/assign-to-me`, где действуют проверка доступа,
расписание и подтверждение замены активной программы. При `no_match` пользователь может изменить
параметры, выбрать существующий шаблон вручную или создать свою программу.
