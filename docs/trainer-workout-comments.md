# Контекстные комментарии тренера

Комментарии относятся только к конкретной тренировке клиента и, опционально, к упражнению
внутри неё. Это не общий чат: API не принимает свободный recipient или контекст вне workout.

## Доступ и история

- Новый комментарий и редактирование доступны только тренеру из текущей active-связи с
  владельцем тренировки. Роль администратора сама по себе не даёт доступ к записи.
- Клиент читает комментарии только к собственным тренировкам.
- После завершения связи новые комментарии и редактирование запрещены. Бывший тренер может
  читать только историю, созданную в рамках своих прошлых связей с этим клиентом. История
  следующего тренера ему недоступна.
- Каждый новый комментарий создаёт отдельную хронологическую запись. При редактировании
  предыдущее тело сохраняется в `workout_comment_revisions`; текущая запись получает
  `updated_at`.

Тело ограничено 2000 символами и имеет формат `plain_text`. HTML не интерпретируется backend-ом;
клиент должен выводить его только через безопасный text rendering.

Каждый новый draft отправляется с `Idempotency-Key`. Повтор запроса с тем же ключом и тем же
содержимым возвращает исходный комментарий и не создаёт второе уведомление. Повторное
использование ключа для другого текста или контекста возвращает `409`. Для старых клиентов
заголовок остаётся опциональным; защита действует для запросов, которые его передают.

## Уведомления

Создание комментария добавляет запись в существующую очередь уведомлений. В Telegram уходит
только короткий preview и кнопка с внутренним `/app` URL, содержащим идентификаторы workout,
comment и, при наличии, workout exercise. Полный комментарий остаётся источником истины в API.
Если Telegram identity не связана, worker отменяет внешнюю доставку, но запись остаётся доступна
в истории in-app уведомлений. Action URL не заменяет серверную проверку доступа к комментариям.

## Интерфейс

Обратная связь показывается внутри конкретной тренировки, а не в отдельном чате. Тренер перед
отправкой видит клиента, дату, тренировку и выбирает всю тренировку либо одно из её упражнений.
Клиент открывает тот же контекст из истории, расписания или внутренней ссылки уведомления.

История остаётся хронологической и показывает автора, время и признак редактирования. Composer
выводит plain text, ограничивает ввод 2000 символами, сохраняет текст при исправимой ошибке и
становится недоступным, если backend сообщает о завершённой связи. Replies, reactions, attachments,
read receipts и отдельный inbox не создаются.
