# Тренировочные предпочтения и ограничения

Тренировочные предпочтения — необязательный немедицинский контекст профиля. Он помогает
детерминированному подбору программ, совместимым заменам и явной проверке уже активной программы.
Пустые поля означают состояние «без ограничений»; первоначальный onboarding не запрашивает эти
данные.

## Контракт данных

`UserProfileUpdate.training_preferences` принимает один объект со следующими полями:

- `preferred_duration_min` и `preferred_duration_max` — необязательный диапазон от `10` до `240`
  минут; минимальное значение не может превышать максимальное;
- `preferred_weekdays` — уникальные номера дней `0..6`, где `0` — понедельник;
- `preferred_time` — необязательное обычное локальное время тренировки;
- `location_profiles` — не более одного профиля для каждого значения `gym`, `home`, `other`; у
  каждого профиля свой набор канонических `equipment_ids` из exercise domain;
- `preferred_exercise_ids` — уникальные ID видимых пользователю системных или личных упражнений;
- `avoided_exercises` — уникальные ID видимых упражнений с необязательной немедицинской причиной
  `not_enjoyable`, `uncomfortable`, `not_confident` или `other`;
- `note` — необязательная заметка до `500` символов.

Одно упражнение нельзя одновременно отметить как предпочитаемое и избегаемое. Backend проверяет
границы, уникальность и доступность упражнения для владельца профиля. Пустой список оборудования
означает отсутствие отдельного инвентаря; `bodyweight` хранится явно и остаётся каноническим
идентификатором собственного веса.

Модель не собирает диагнозы, противопоказания и план лечения. В интерфейсе всегда показывается
граница: приложение не оценивает боль или травму и направляет к специалисту.

## Изменение и права доступа

- пользователь изменяет свои настройки через `PATCH /api/v1/me/profile`;
- тренер использует существующий `PATCH /api/v1/coach/clients/{client_id}/profile` только при
  активной связи с этим клиентом;
- прекращение связи немедленно закрывает trainer endpoint;
- `updated_at` и `updated_by` позволяют владельцу увидеть автора последнего фактического изменения;
  повторная отправка неизменённого объекта не переписывает автора и время.

Permission model не расширен: frontend не является границей авторизации, ID владельца не берётся из
payload пользовательского endpoint. Audit event тренера содержит только список изменённых полей,
но не текст заметки и не полный payload.

## Подбор и адаптация

`POST /api/v1/programs/templates/recommendation` использует единственный профиль места и его
оборудование как default, если мастер не передал явное переопределение. При нескольких местах
мастер выбирает конкретный профиль. Кандидаты с упражнением из `avoided_exercises` исключаются;
наличие предпочитаемого упражнения служит детерминированным tie-break после цели, частоты, split и
уровня. Это product heuristic, а не научная или медицинская оценка.

Workout adaptation по-прежнему выбирает только curated alternatives с совместимым оборудованием.
Дополнительно вариант из `avoided_exercises` владельца не возвращается и не применяется. Запрос о
боли или травме сохраняет прежний `safety_stop` и не превращает avoid-list в лечебную рекомендацию.

## Конфликт с активной программой

Сохранение предпочтений никогда не удаляет, не архивирует и не переписывает активную программу.
Ответ профиля возвращает `conflict.status=review_required`, если будущие или начатые тренировки
могут противоречить выбранным дням, времени, диапазону расчётной длительности, инвентарю или
avoid-list. Причины отображаются в том же flow вместе с явным переходом к проверке программы.

Расчётная длительность использует ту же консервативную эвристику, что и workout adaptation:
`45` секунд на назначенный подход, сохранённый отдых между подходами и `60` секунд на переход к
упражнению. Это ориентир для review, а не прогноз фактической длительности.

## Privacy lifecycle

Настройки принадлежат владельцу профиля, хранятся в `user_profiles` и удаляются вместе с аккаунтом.
Они включены в `GET /api/v1/me/export`; удалённый аккаунт тренера оставляет у клиента сами
предпочтения, но обнуляет FK автора изменения. Новых внешних получателей, analytics properties и
логирования содержимого нет.

Черновик формы хранится в user-scoped ключе `fit_training_preferences_draft_{user_id}`. Он содержит
только редактируемые поля, переживает исправимую сетевую ошибку, theme/viewport events и удаляется
при logout, подтверждённой смене аккаунта или удалении аккаунта вместе с другими sensitive drafts.

## Миграция

Миграция `0054_training_preferences` добавляет nullable scalar fields, JSON-списки с пустыми
server defaults, FK автора с `ON DELETE SET NULL` и DB checks диапазона/порядка длительности и длины
заметки. Existing profiles получают состояние «без ограничений» без backfill предположений.
