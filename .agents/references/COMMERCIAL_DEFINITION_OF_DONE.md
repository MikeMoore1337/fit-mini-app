# Commercial Definition of Done

Используй как базовую рамку. Удаляй пункты, неприменимые к типу продукта.

## Product
- Критические сценарии соответствуют acceptance criteria.
- Нет известных блокирующих дефектов.
- Ошибки имеют понятное пользовательское/программное поведение.

## Code
- Изменение не содержит ненужного scope.
- Нет обходов линтера/типов без причины.
- Зависимости оправданы и закреплены lockfile/эквивалентом.

## Data
- Инварианты защищены на подходящем уровне.
- Миграции воспроизводимы.
- Destructive changes имеют безопасную стратегию.
- Для критических данных есть понятная стратегия backup/restore.

## Security
- AuthN/AuthZ проверяются на доверенной стороне.
- Секретов нет в коде/логах.
- Внешние входы валидируются.
- Критические abuse paths рассмотрены.

## QA
- Unit/integration/e2e покрытие соответствует риску.
- Negative paths проверены.
- Regression test добавлен для существенного исправленного дефекта, где это целесообразно.

## UI
- Desktop/mobile проверены, если применимо.
- Keyboard/focus/contrast/labels проверены.
- Нет overflow/overlap на поддерживаемых размерах.
- Loading/error/empty states существуют там, где нужны.

## Performance
- Нет очевидных N+1/unbounded operations.
- Критический performance path измерен, если риск существенный.

## Operations
- Конфигурация отделена от кода.
- Есть health/readiness для сервиса, если требуется.
- Logs/metrics позволяют расследовать критический сбой.
- Deployment и rollback понятны.

## Documentation
- Setup и команды актуальны.
- Миграции/deployment описаны, если не полностью автоматизированы.
- Существенные ограничения зафиксированы.
